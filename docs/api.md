# API

`openapi/clypeus-v1.json` is the machine-readable contract; it is generated by
`clypeus --print-openapi` and checked for drift in CI. This page summarizes
the surface.

## Authentication

Every `/v1` and `/admin/v1` route requires `Authorization: Bearer <token>`.
The principal carries an opaque scope; all data access is partitioned by it.
Administrative routes additionally require a principal holding a configured
admin scope.

## Completions

* `POST /v1/completions` — provider-agnostic completion. Buffered by default;
  `"stream": true` returns SSE. The guard runs before the provider call.

## Models

* `GET /v1/models` — catalog for the scope's configured provider.
* `POST /v1/models/preview` — catalog for an ad-hoc base URL and key.

## Threads and turns

* `GET|POST /v1/threads`, `GET|PATCH|DELETE /v1/threads/{id}`
* `POST /v1/threads/{id}/messages` — run a turn (buffered or streamed).
* `PATCH /v1/messages/{id}` — edit a user message (creates a sibling version).
* `POST /v1/messages/{id}/regenerate` — regenerate an assistant message.
* `POST /v1/messages/{id}/activate` — switch the active branch.
* `PUT|DELETE /v1/messages/{id}/feedback`
* `GET /v1/threads/{id}/usage` — token usage across the thread.

### Reasoning levels

`reasoningLevel` is an open string. A turn or function accepts a value only
when the effective model's catalog advertises it verbatim (case-sensitive);
absent, empty, and `"default"` always mean "no explicit override" and send no
reasoning parameter. Accepted values are forwarded to the provider unchanged,
and `POST /v1/completions` forwards any value verbatim without catalog
validation.

### SSE events

Text and reasoning stream as anonymous `data:` chunks
(`{"delta":{"content"|"reasoning": "..."}}`), usage as
`{"usage": {...}}`. Structured events:

* `event: context` — the turn context snapshot, emitted first.
* `event: tool_call` — `{ id, name, arguments, risk, state, approval? }`.
* `event: tool_result` — `{ id, name, state, result? , error?, durationMs }`.
* `event: turn_completed` — the persisted turn view.
* `data: [DONE]` — terminal sentinel.

## Approvals

* `POST /v1/tool-calls/{id}/approvals` — body
  `{ decision, argumentsHash, typedConfirm?, stream? }`. `allow` executes the
  parked call once; `deny` records a refusal. Replays, expired windows, and
  hash mismatches are rejected with stable codes.

## Tools and functions

* `GET /v1/tools` — the scope-filtered tool catalog.
* `GET /v1/functions`, `POST /v1/functions/{name}` — function registry and
  execution. Inputs are strictly validated; outputs are validated and, where
  configured, repaired within a bounded retry budget.

## Audit

* `GET /v1/audit`, `GET /v1/audit/export` — append-only records with redacted
  arguments and a canonical arguments hash.

## Administration

* `GET|PUT /admin/v1/scopes/{scope}/settings`
* `POST /admin/v1/scopes/{scope}/settings/test`
* `POST /admin/v1/scopes/{scope}/models/preview`

## Operations

* `GET /healthz` — dependency-free liveness.
* `GET /readyz` — store readiness; `503` with a detail on failure.
* `GET /metrics` — Prometheus text format with the `clypeus_` prefix.
* `GET /openapi/v1.json` — this contract.
